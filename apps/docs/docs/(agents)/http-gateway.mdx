`@howells/fieldwork-mcp` also exports a gateway: one web-standard `fetch` handler that serves every tool as a JSON API and as MCP over Streamable HTTP. Provider keys stay on the server, and each agent gets its own key.

| Route | Method | What it does |
| --- | --- | --- |
| `/api/v1/openapi.json` | `GET` | OpenAPI 3.1 for this gateway: only the tools and providers it serves. No key needed. |
| `/api/v1/tools` | `GET` | Each tool's name, providers, input schema and output schema. |
| `/api/v1/tools/{name}` | `POST` | Runs one tool. The JSON body is the tool's input. |
| `/mcp` | `POST` | The same tools as an MCP server. |

The [API reference](/reference) renders the description of this site's own gateway, one page per tool.

## Call it

```sh
curl https://example.com/api/v1/tools/search_web \
  -H "authorization: Bearer $FIELDWORK_AGENT_KEY" \
  -H "content-type: application/json" \
  -d '{"query": "framework laptop 13 review", "limit": 5}'
```

```json
{ "requestId": "…", "provider": "exa", "result": { "results": [] } }
```

Each tool has a default provider. Set `provider` in the body to choose another one that serves the tool; the gateway never switches providers after an error. `timeout` caps the wait in milliseconds, at 45 seconds. A long job that outlasts it fails with `Timeout` and a `jobId`; send the `jobId` back as `resume` to collect it.

For an MCP client:

```sh
claude mcp add --transport http fieldwork https://example.com/mcp \
  --header "Authorization: Bearer $FIELDWORK_AGENT_KEY"
```

## Keys

Every request except `openapi.json` needs `Authorization: Bearer <key>`. A missing or wrong key gets a `401` with `WWW-Authenticate: Bearer`, before any provider is called.

`gatewayFromEnvironment` reads the keys from the environment:

| Variable                         | Agent id in the call log              |
| -------------------------------- | ------------------------------------- |
| `FIELDWORK_API_KEY`              | `owner`                               |
| `FIELDWORK_AGENT_<NAME>_API_KEY` | `<name>`, lower-cased with `_` as `-` |

Keys are at least 32 characters, and each agent's key must be distinct. The gateway compares hashes in constant time and removes every agent key from error messages; `gatewayFromEnvironment` removes the provider keys too. To revoke a key, remove its variable and redeploy; the other agents keep their access. Provider keys use the names in [Keys](/docs/keys), and only providers with a key are served.

Each tool call's log entry goes to `onCall`: the agent id, request id, tool, provider, outcome, duration, error code, `jobId` and reported usage, never the input, the result or a key. This site writes every entry to its logs. A failing `onCall` never changes the response, and an unexpected error's message goes only to stderr: the caller sees a fixed 500.

## Errors

Every failure has the same body, and every response carries `x-request-id`:

```json
{
  "error": {
    "code": "Unauthorized",
    "message": "A valid Fieldwork bearer key is required",
    "retryable": false
  },
  "requestId": "…"
}
```

Branch on `error.code`, which is one of the [error codes](/docs/errors). `retryAfter`, `provider` and `jobId` appear when they apply, and a rate limit also sets `Retry-After`. Every error response links here with `Link: <…>; rel="help"`.

| Status | Codes |
| --- | --- |
| `400` | `InvalidRequest`, `Unsupported`: a query string, invalid JSON, or input the tool refuses. |
| `401` | `Unauthorized`: no key, or a wrong one. |
| `403` | `Unauthorized`: a cross-origin browser request. |
| `404` | `NotFound`: an unknown route or tool, or a page or job the provider cannot find. |
| `408` | `Timeout`: the body did not arrive within 5 seconds. |
| `405`, `413`, `415` | `InvalidRequest`: the wrong method, a body over 2 MiB, or a body that is not `application/json`. |
| `429` | `RateLimited`: wait `retryAfter` seconds. |
| `502` | `ProviderError`, `JobFailed`, `Aborted`, or `Unauthorized` from the provider: the gateway's provider key failed, not yours. |
| `500` | `ProviderError`: an unexpected failure in the gateway. |
| `504` | `Timeout`. |

For large public documents, send `parse_document` a `url` and set `provider` to `llamaparse` or `reducto`. Each provider fetches the document directly. Use `name` and `contentBase64` for inline bytes, never together with `url`. Base64 expands bytes by about one third, so the 2 MiB JSON-body limit holds less than 1.5 MiB of file. This conservative budget stays below Vercel's 4.5 MB request limit. An oversized body returns HTTP 413 with `InvalidRequest`, the byte limit and the URL alternative. Firecrawl's parse endpoint accepts uploads only; use `read_page` for its public document URLs.
