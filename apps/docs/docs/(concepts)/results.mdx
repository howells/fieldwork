Alongside `raw`, most results carry `meta` when the provider sends one.

## The provider's response

`raw` holds exactly what the provider sent, so nothing is lost by normalizing it. Reach for it when you need a field Fieldwork doesn't map.

```ts
const page = await web.read("https://frame.work/laptop13");

page.markdown; // the page as Markdown
page.raw; // the provider's own response
```

[Agent tools](/docs/agent-tools) strip `raw` before a model sees a result. The SDK never does.

<AccordionItem title="What each method returns">

- `search` returns `{ results, answer, images, meta, raw }`. Each result has `url`, `title`, `snippet` and, when the provider has them, `content`, `publishedAt`, `author`, `image`, `favicon` and `score`. Shopping, place, news, scholar and patent results set `kind` and carry `price`, `rating`, `reviewCount` and `place`.
- `read` returns a `Page`: `url`, `title`, `description`, `markdown`, `html`, `links`, `images`, `image` (the page's main image), `excerpts`, `summary`, `publishedAt`, `author`, `language`, `statusCode` and `screenshot`, as the provider has them.
- `readMany` returns `{ pages, failed }`. A URL that could not be read is listed in `failed` with the reason; it does not throw.
- `extract` returns `{ data, fields }`. `data` follows your schema; `fields` lists each field's citations when the provider returns them.
- `product` returns the product and its `variants`, each with `sku`, option `values`, `price` (`amount`, `currency`, `formatted`), `originalPrice`, `availability`, `gtin` and `images` (`{ url, alt }`).
- `answer` returns `{ answer, output, citations, continuationId }`.
- `research` returns `{ id, status, output, sources, fields, continuationId }`. `output` follows your schema when you pass one, otherwise it is the report text.
- `crawl` returns `{ pages, failed, robotsBlocked, total }`.
- `download` returns `{ url, bytes, contentType, size, statusCode, etag, lastModified }`: `url` is the final URL, `bytes` a `Uint8Array` exactly as served, `contentType` the server's header unchanged. Browserbase and Kernel also return `etag` and `lastModified`.
- `parse` returns `{ id, markdown, pages, blocks, pageCount }`. With `blocks: true`, `blocks` lists the layout in reading order, each block with its `page`, `type`, `text` and `box`. With `wordBoxes: true`, LlamaParse and Reducto add `words` and table `cells`, each with its own box. LlamaParse also adds `lines` to each block and each cell, each `{ text, box }`, the text being the line's part of the block's or cell's text, Markdown included; Reducto places no lines. LlamaParse gives a cell in several boxes each of them as `boxes` (`box` encloses them), marks a block read out of a page header or footer with `container`, and with `blocks` or `wordBoxes` gives each page its `width` and `height` in points. With `pageImages: true` (LlamaParse), each page carries `image`, an address for a picture of the page that expires after about an hour; `parse({ resume: id, pageImages: true })` collects fresh addresses without the file: one request that reads the finished job, with no new parse and no credits charged. LlamaParse draws no pictures of a spreadsheet (xlsx, xls, csv, ods and the like), so a spreadsheet's pages come back without `image`. LlamaParse does not publish how long it keeps a job's result; plan for 48 hours and treat `NotFound` on resume as a job to parse again.

</AccordionItem>
<AccordionItem title="Pages that don't exist">

A page that answered 404 or 410 is not returned. `read` throws `NotFound` on every provider, and `readMany` lists the URL in `failed`.

</AccordionItem>
<AccordionItem title="Jobs that stop early">

A job that stopped early but produced output, for example on a credit or step limit, returns `status: "partial"` with `stopReason`. A job with no usable output throws `JobFailed`.

</AccordionItem>
